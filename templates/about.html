About Video Learning Platform

Video Learning Platform is a clean, responsive, and robust academic mini project developed for college student demonstration in Mobile & Web Programming (MWP). It offers a distraction-free environment for students to master 5 foundational computer science topics through real, embeddable YouTube video lessons and personalized progress tracking.

Unlike commercial platforms bloated with third-party trackers, popups, and complex front-end frameworks, this application adheres strictly to standard web engineering fundamentals: clean semantic HTML, modular Vanilla CSS, lightweight client-side JavaScript, Python Flask backend routing, secure Werkzeug password hashing, and persistent SQLite database storage.

Core Technologies & Architecture

1. HTML5

Semantic page structuring using <header>, <nav>, <main>, <section>, <aside>, and <footer> along with responsive 16:9 <iframe> embeds for high-definition video playback.

2. Vanilla CSS

Custom CSS design tokens, flexible grid layouts, responsive media queries, card components, and accessible form styling without heavyweight third-party CSS dependencies.

3. Vanilla JavaScript

Asynchronous AJAX requests via Fetch API for instantaneous lesson completion toggles, interactive status badges, dynamic progress toasts, and mobile navigation toggling.

4. Python Flask

Lightweight WSGI framework managing HTTP routes, Jinja2 template rendering, authentication decorators (@login_required), and secure cookie-based session state.

5. SQLite Database

Serverless, self-contained relational database storing students, lessons, and completion records with relational integrity, foreign key constraints, and dynamic SQL aggregation.

6. Werkzeug Security

Industrial-standard password hashing using generate_password_hash() and check_password_hash() to guarantee student passwords are never stored in plain text.

The 5 Foundational Lessons

  1. Lesson 1: Introduction to Python — Syntax basics, dynamic typing, variables, indentation rules, and first print script.
  2. Lesson 2: HTML Basics — Semantic tags, headings, paragraphs, lists, links, forms, and web document structure.
  3. Lesson 3: CSS Basics — Styling selectors, typography, colors, layout rules, flexbox, and the CSS box model.
  4. Lesson 4: JavaScript Basics — Scripting fundamentals, variables, functions, event handling, and dynamic DOM manipulation.
  5. Lesson 5: SQL/Database Basics — Relational database concepts, tables, primary/foreign keys, and CRUD queries (SELECT, INSERT, UPDATE, DELETE).

Database Schema Design (platform.db)

The SQLite database implements 3 normalized relational tables:

  • 1. students: id (PK), name (TEXT), email (TEXT, UNIQUE), password_hash (TEXT), created_at (TIMESTAMP)
  • 2. lessons: id (PK), lesson_number (INTEGER, UNIQUE, 1-5), title (TEXT), description (TEXT), video_id (TEXT), embed_url (TEXT), duration (TEXT), summary_notes (TEXT)
  • 3. progress: id (PK), student_id (FK → students.id), lesson_id (FK → lessons.id), is_completed (INTEGER 0/1), completed_at (TIMESTAMP), UNIQUE(student_id, lesson_id)

Key Teacher Viva Q&A Highlights

  • Q: How are user passwords secured?
    Answer: Passwords entered during registration are securely hashed via Werkzeug's generate_password_hash() using cryptographic salting (PBKDF2/scrypt). During login, check_password_hash() validates the credential against SQLite. Plain passwords are never stored.
  • Q: Why are YouTube videos embedded via iframes instead of HTML5 <video>?
    Answer: YouTube watch URLs cannot be directly streamed by browser HTML5 <video> tags due to CORS and streaming protocol requirements. Proper YouTube embed URLs (https://www.youtube.com/embed/VIDEO_ID) loaded inside responsive 16:9 <iframe> elements allow YouTube's player to legally and reliably stream educational content.
  • Q: How does student progress isolation work?
    Answer: The progress table enforces a composite uniqueness on (student_id, lesson_id). All SQL queries filter with WHERE student_id = session['student_id'], meaning Student A marking lessons completed never affects Student B.
  • Q: How does dynamic progress calculation prevent tampering?
    Answer: Progress is computed directly on the server via SQLite: (COUNT(completed) / 5) * 100. This avoids relying on insecure browser localStorage or fake JavaScript counters.
